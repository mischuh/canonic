---
title: "canonic sl"
description: "Semantic layer: resolve, compile, and describe."
---

`canonic sl` exposes the semantic-layer capabilities directly: useful for debugging what a metric resolves to or what SQL a query compiles down to, without executing anything.

<Note>
  With `--json`, each of these commands' output matches its corresponding MCP tool payload byte-for-byte (`resolve_metric`, `compile_query`, `describe_metric`).
</Note>

## `sl resolve`

Resolve a name to its canonical binding.

```bash
canonic sl resolve revenue
canonic sl resolve revenue --context finance_review
```

| Argument / Flag | Description |
| --- | --- |
| `name` | Metric/dimension name (positional). |
| `--context` | Tag for context-scoped guardrail resolution. |

Prints the resolved metric, owning source, measure, and binding kind.

With `--json` the payload also carries `kind`, `components` and `population_filter`. For a composite metric (`ratio`, `weighted_avg`) `source` and `measure` are `null` and `components` names the numerator, the denominator and the `on_zero_denominator` policy:

```json
{
  "metric": "margin",
  "kind": "ratio",
  "source": null,
  "measure": null,
  "components": { "numerator": "profit", "denominator": "revenue", "on_zero_denominator": "null" },
  "population_filter": null
}
```

## `sl compile`

Compile a semantic query to SQL + metadata without executing it.

```bash
canonic sl compile --metrics revenue --dimensions order_date
canonic sl compile --file query.json
```

| Flag | Description |
| --- | --- |
| `--metrics` | Metric name(s): comma-separated and/or repeatable. |
| `--dimensions` | Dimension name(s): same comma/repeat rules as `--metrics`. |
| `--filter` | A filter as `field=value` or `field:op:value` (repeatable). |
| `--via` | Join-path alias prefix (comma-separated and/or repeatable) to disambiguate an `ambiguous_join_path` error. |
| `--limit` | Row cap injected by the dialect adapter. |
| `--file`, `-f` | Semantic query JSON file. |

`--metrics`/`--dimensions`/`--filter`/`--via`/`--limit` and `-f` are mutually exclusive, same as `canonic query`. See [`canonic query`](/cli-reference/query-sql-assert) for the full filter syntax. The flags build the identical `SemanticQuery` a JSON file would deserialize: `{"metrics": [...], "dimensions": [...], "filters": [...], "via": [...], "limit": null}`. Output includes the target dialect, the compiled SQL, resolved bindings, and any guardrails that fired.

## `sl describe`

Return grain, dimensions, measures, and freshness for one metric.

```bash
canonic sl describe revenue
```

| Argument | Description |
| --- | --- |
| `name` | Metric name or alias (positional). |

Prints the metric's source, grain, dimensions, freshness (`last_validated_at`), and any worked examples on file.

For a composite metric there is no single source. `--json` then returns `kind`, `components` and `population_filter` as for `sl resolve`, `measures` lists the measures its components read, and `grain` is the shared grain when both components sit on one source, otherwise empty.
